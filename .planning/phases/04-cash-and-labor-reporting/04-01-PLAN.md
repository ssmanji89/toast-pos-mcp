## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP input → report builder | An untrusted business date and optional restaurant GUID select a report request. |
| Runtime location/capability → Toast cash API | The report crosses into restaurant-scoped business data after location and scope authority are resolved. |
| Toast source payload → aggregate result | Untrusted upstream cash/deposit payloads become an operator-visible deterministic summary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T4-CASH-01 | Information disclosure | `src/cash-report.ts` source requests | mitigate | Use selected `restaurantGuid` on every cash/config request and do capability preflight before reads. |
| T4-CASH-02 | Tampering | cash fold | mitigate | Strict schemas, integer minor units, observed reversal handling, and denial on malformed data prevent changed or missing data from becoming zero totals. |
| T4-CASH-03 | Elevation of privilege | capability preflight | mitigate | Require the intersection-backed `cashmgmt:read` and `config:read` decision before business reads. |
| T4-CASH-04 | Information disclosure | report serialization | mitigate | Return aggregates, identifiers only where needed for unresolved references, bounded provenance, and no raw upstream bodies. |
| T4-CASH-SC | Tampering | dependency supply chain | accept | This plan installs no package; exact-head Node/package gates occur in Plan 04-03. |
</threat_model>
