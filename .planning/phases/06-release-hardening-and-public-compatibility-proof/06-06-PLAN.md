<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| Canonical source to inventory | Repository and GitHub source text becomes a formal normalized requirement. |
| Inventory to evidence matrix | A formal requirement becomes a separate implementation and evidence claim. |
| Local evidence to release control plane | Tests, commands, and reviews may describe local proof but cannot supply external authority. |
| Reviewer to control plane | A non-builder evaluates the exact candidate and reports findings. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T6-006-01 | Tampering | requirements inventory | mitigate | Source commit, exact quote, path or URL, heading, and unique ID make every requirement traceable. |
| T6-006-02 | Repudiation | evidence matrix | mitigate | Separate implementation, local evidence, review, reachability, live proof, and external-gate fields retain evidence limits. |
| T6-006-03 | Spoofing | release status | mitigate | The audit rejects gate closure based on synthetic tests, merged PRs, or local agent review. |
| T6-006-04 | Information disclosure | audit artifacts | mitigate | Use source metadata and invented test fixtures only. Store no credential, token, raw vendor body, or Merchant Data. |
| T6-006-05 | Elevation of privilege | gate classification | mitigate | Mandatory rows preserve #60, #28, T5-003-G01, consent, Terms or brand, signing, publication, and live compatibility as owner-controlled gates. |
| T6-006-SC | Tampering | package supply chain | accept | This plan adds no package. Verification uses the committed lockfile only when tests need a restore. |
</threat_model>
